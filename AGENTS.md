# Инструкции для ИИ-агентов (onwin)

Этот файл — главный источник правил для любого ИИ-агента в репозитории (Claude Code читает его через `CLAUDE.md`).
Правила здесь важнее памяти агента. Если правило устарело, исправьте этот файл в том же коммите, где меняется поведение.

## Что такое onwin

Бесплатное приложение с открытым кодом (GPL-3.0) для запуска Windows-программ, в первую очередь игр, на Mac с Apple Silicon.
Движок — Wine 11 из открытых исходников CrossOver от CodeWeavers (LGPL) плюс DXVK, DXMT, MoltenVK, GStreamer. Интерфейс
и устройство — собственные.

```
app/            Swift-пакет: OnwinCore (вся логика), OnwinApp (SwiftUI), onwinctl (CLI), onwin-launcher (ярлыки)
engine/         сборка движка: build-libs.sh, build.sh, compat/onwincompat.c, patches/, README.md
scripts/        build-app.sh (Onwin.app), release.sh (релизы), collect-licenses.sh, build-cabextract.sh, …
site/           сайт GitHub Pages (статический, без сборщиков), install.sh — установщик «одной командой»
third_party/    тексты лицензий сторонних компонентов (кладутся в приложение и движок)
.github/        workflow публикации сайта
```

## Общение с пользователем

- Пишите по-русски. Пользователь не специалист по Wine и macOS: перед любым выбором простыми словами объясните, что это
  такое и чем отличаются варианты.
- Вопросы и выбор вариантов — через инструмент вопросов с вариантами ответа (AskUserQuestion), а не текстом в чате.
- Заранее предупреждайте о любом окне, которое потребует действий пользователя: системные запросы macOS, ввод пароля,
  установщики Windows-программ, вход в GitHub/Apple ID. Скажите, что появится и что нажать. По возможности делайте шаги
  тихими (ключи тихой установки, Mono/Gecko внутри движка).

## Чистая комната: авторские права и лицензии (обязательно)

onwin публичный. Любая ошибка здесь — юридический риск для автора.

1. **Закрытые продукты не используются как источник.** Ни для кода, ни для данных, ни для текстов, ни для «идей
   реализации по внутренностям» нельзя брать закрытую часть CrossOver.app и других закрытых продуктов: бинарники,
   `.pyc`, Perl-обёртки, `crossover.tie`, `cxfixes.xml`, базы совместимости, файлы локализации, ресурсы и иконки.
   Не запускайте на них `strings`, `nm`, `otool`, дизассемблер и не читайте их файлы. Лицензия CrossOver это запрещает.
2. **Открытые исходники использовать можно** (исходники CrossOver от CodeWeavers под LGPL, Wine, DXVK, DXMT и т. д.), с
   указанием источника: путь к файлу или номер «CW HACK» из *открытого* дерева.
3. **Каждое правило совместимости** (`CompatDB.swift`, настройки компонентов в `Catalog.swift`, ключи запуска в рецептах)
   сопровождается комментарием-источником: публичная ссылка (WineHQ AppDB, ProtonDB, баг-трекер, документация) или
   «onwin test, <дата>, <Mac/macOS>». Без источника правило не добавляется.
4. **Тексты интерфейса — свои.** Не переводите и не копируйте формулировки чужих программ.
5. **Товарные знаки** (CrossOver, Windows, DirectX, Steam, Apple…) — только чтобы указать совместимость или происхождение
   открытого кода. Никаких чужих логотипов, скриншотов игр и обложек на сайте и в репозитории. Исключение — значки сервисов
   на ссылках, ведущих на этот сервис (Telegram, GitHub), как разрешают их правила использования бренда. onwin не называем
   «клоном» или «заменой» CrossOver.
6. **Не распространяем:** D3DMetal / Game Porting Toolkit (пользователь скачивает сам), компоненты Microsoft (качаются
   с серверов Microsoft на машине пользователя), игры и их ресурсы.
7. **Внутренние заметки и исследования** (сравнения с другими продуктами, черновики) хранятся только в закрытом
   репозитории `onwin-notes` или в локальной папке `notes/` (она в `.gitignore`), никогда в этом репозитории.
8. **Новый или обновлённый сторонний компонент** в движке или приложении: обновить `scripts/collect-licenses.sh` и
   `third_party/licenses/`, таблицу в `THIRD_PARTY_NOTICES.md` и `site/licenses.html`, а исходники компонента приложить
   к релизу движка (`scripts/release.sh engine`). Лицензия должна позволять распространение; GPL-несовместимое — не
   добавлять без согласования с пользователем.

## Терминология

- Изолированная среда Windows со своим диском C: называется **«пространство»** (в коде `Space`, `SpaceConfig`,
  `SpaceManager`, CLI `onwinctl spaces`, папка `~/Library/Application Support/onwin/Spaces`). Слово «бутылка»/bottle
  не используем нигде.
- Совместимость со старыми сборками не ломать: папка `Bottles` переносится автоматически (`OnwinPaths.migrateLegacySpaces`),
  читаются `onwin-bottle.json`, ярлыки `onwin://run?bottle=`, рецепты с ключом `bottleName`, архивы `.onwinbottle`.

## Версии

Всегда последние стабильные версии инструментов, библиотек и GitHub Actions, без легаси. Перед закреплением версии
проверьте актуальный релиз. Исключения объясняйте пользователю: Wine Mono/Gecko должны точно совпадать с версией Wine
(`dlls/appwiz.cpl/addons.c`); DXVK на Mac ограничен возможностями MoltenVK.

## Сборка и проверка

```bash
cd app && swift build -c release          # компиляция всех целей
scripts/build-app.sh                       # Onwin.app → build/app.noindex/Onwin.app (и обновляет /Applications/Onwin.app)
engine/build-libs.sh && engine/build.sh    # движок → engine/dist/onwin-cx26.3 (долго, см. engine/README.md)
```

Перед коммитом: `swift build` без ошибок. После изменений в запуске Wine, правилах совместимости или Steam проверьте
реальный запуск (`onwinctl run <пространство> <exe>`), прежде всего Steam в пространстве пользователя «Игры» — его
окно не должно быть чёрным. Данные пользователя (`~/Library/Application Support/onwin`) не удаляйте; для опытов
используйте `ONWIN_HOME=<временная папка>`.

Подсказка по правке файлов: не используйте `perl -pi` с `s|…|…|` и `\|` в шаблоне (портит файлы), берите python.

## Git и публикация

- Работа идёт в `main` (или в ветке worktree, которая потом вливается в `main`). После каждого законченного этапа —
  коммит с понятным сообщением на английском и строкой `Co-Authored-By`, которую задаёт среда агента.
- Публичный репозиторий: `github.com/<владелец>/onwin`. `git push`, создание релизов и изменение настроек GitHub —
  только по просьбе пользователя.
- Не коммитить: исходники и сборку движка (`engine/sources`, `engine/build`, `engine/dist`), `build/`, `dist/`, `notes/`,
  токены, ключи, личные данные.

## Релизы и установщик

Подробно — в начале `scripts/release.sh`. Коротко:

- **Релиз движка** (`engine-<id>-<сборка>`, не «latest»): `onwin-engine-<id>.tar.xz`, манифест с SHA-256 и архивы
  исходников всех LGPL/GPL/MPL-компонентов. Выпускается только при изменении движка.
- **Релиз приложения** (`v<версия>`, «latest»): `Onwin-<версия>.dmg` (приложение с движком внутри),
  `Onwin-<версия>-app.zip` (без движка), `onwin-release.json` (версии, ссылки, SHA-256 частей), `install.sh`.
- Размер важен: у многих пользователей медленный интернет. Движок перед упаковкой проходит этап `slim`
  (`engine/build.sh`), архив сжимается `xz` с x86-фильтром и большим словарём (`ENGINE_XZ` в `release.sh`).
  install.sh и приложение распаковывают его системным `/usr/bin/tar`: другой формат — только такой, который он
  читает без дополнительных программ (zstd — нет).
- `site/install.sh` читает `onwin-release.json` последнего релиза и скачивает только изменившиеся части: приложение
  в `/Applications` (или `~/Applications`), движок в `~/Library/Application Support/onwin/Engines/<id>`. curl не ставит
  карантин, поэтому Gatekeeper не блокирует запуск неподписанного приложения.
- Встроенное обновление (`app/Sources/OnwinCore/Updater.swift`: меню «Проверить обновления…», баннер, `onwinctl update`)
  читает тот же `onwin-release.json`, что и `install.sh`: формат меняйте только вместе с ним (поле `schema`). Репозиторий
  задаёт `OnwinLinks.repository`. Сравнивается `build` с CFBundleVersion и `engine.built` с `onwin-engine.json`.
  Автопроверка — только с согласия: при первом запуске onwin один раз спрашивает, до ответа в сеть не ходит.
- Версии ниже 1.0 — бета: людям версия показывается как «0.1.1 (бета)» (`OnwinVersion.display`).
- Версия приложения — `OnwinVersion.string` в `app/Sources/OnwinCore/WineRunner.swift`.
- Приложение не нотаризовано (нет Apple Developer ID). Не обещайте пользователям обратного.
- Подпись: собственный самоподписанный сертификат «onwin Code Signing» в связке ключей автора
  (`scripts/make-signing-identity.sh`, `build-app.sh` находит его сам). Он даёт приложению постоянную «личность», и macOS
  помнит разрешения (микрофон, камера, папки) между обновлениями. Релизы подписываются только им; ad-hoc-сборки для
  релиза не годятся. Ключ никогда не кладётся в репозитории, резервная копия — у автора.

## Сайт

`site/` — чистый HTML/CSS/JS без внешних скриптов и шрифтов, светлая и тёмная темы, ширина от 360 px. Ссылки на пожертвования
(Boosty, Ko-fi, криптоадреса) задаются только в `site/config.js`; пустые значения скрываются. Внизу страниц — одна
короткая строка о товарных знаках; CrossOver на сайте не упоминается. После правки CSS/JS увеличьте `?v=` в ссылках на них. Публикуется workflow
`.github/workflows/pages.yml` при пуше в `main`.
